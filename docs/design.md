# 设计草稿

> 状态：brainstorming，随时改。

## 1. 背景

「三件好事」（Three Good Things / Three Blessings）是 Seligman 提出的感恩练习：每天睡前写下三件当天发生的好事，并说明它为什么让你开心。相关研究里，这类练习常用于提升幸福感。

这个仓库想把它做成一个真正天天愿意打开的小产品。

## 3. 形态对比

| 方案 | 优点 | 代价 | 适合 |
| --- | --- | --- | --- |
| Web / PWA | 跨平台、部署快、改动即时生效 | 推送和相册体验一般 | 先验证想法 |
| 手机 App（React Native / Flutter） | 体验最好、推送自然 | 打包上架成本高 | 长期产品 |
| 微信小程序 | 国内分享方便 | 审核、订阅消息限制 | 面向国内朋友 |
| 先不写代码（手账 / 表格） | 零成本 | 没提醒、没统计 | 先养成习惯 |

## 4. MVP 的最小样子（讨论用）

「能记三条 + 能看到过去 + 数据不丢」就够了。先自己用两周，再决定要不要提醒、统计、分享。

## 6. 决策记录

- 2026-11-16 **形态选 Web**（放弃小程序先行）：绕开小程序审核/类目/AppID；先白嫖 GitHub Pages，以后要小程序再用 uni-app 迁移。
- 2026-11-16 **前端 Vue 3 + Vite + TS**，CSS 手写、不引 UI 库；界面中文、移动优先。
- 2026-11-16 **首版无后端**：localStorage + 导出 JSON/Markdown；存储层单独抽象（`src/lib/storage.ts`），以后换 Go API 只改这一处。
- 2026-11-16 **产品原则**：记录要轻（3 分钟）、回顾要有惊喜、不制造负罪感；不做社交/排行榜/打卡惩罚。
- 2026-11-16 **"为什么" 默认折叠、不强制**：这个练习的效果很大程度来自给好事写归因，但不能逼人写。
